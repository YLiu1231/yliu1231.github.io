Loop Engineering：别再问我什么是循环工程

发表于 2026-06-15 分类于 Self-Learning
从 Prompt、Context 和 Harness 继续向上，理解如何设计可重复运行、有状态、有评判器并保留人工复核点的 Agent 循环。

Loop Engineering 讨论的核心变化，是把人从逐句驱动 Agent 的位置移到循环之外：人不再负责每一次 Prompt，而是设计一套能够发现任务、保存状态、调用 Agent、验证结果并决定是否继续的系统。

这本书讲什么

《Loop Engineering：别再问我什么是循环工程》从概念演化开始，区分 Prompt Engineering、Context Engineering、Harness Engineering 与 Loop Engineering 的职责边界，并把一个可持续运行的 Agent 循环拆成可理解的动作和零件。

书中没有把“自动运行”直接等同于工程完成。循环能否长期工作，还取决于状态能否跨轮保存、评判器能否独立判断、并行任务是否隔离、成本是否有上限，以及关键节点是否保留人工复核。

内容结构

  • 它是什么：解释 Loop Engineering 的定义，以及它相对 Prompt、Context 和 Harness 所处的位置。
  • 它怎么转：拆解循环的五个动作、六个组成部分，以及生成器与评判器的分工。
  • 它在哪运行、付出什么代价：结合真实案例讨论后台执行、验证债、理解腐烂和 Token 失控。
  • 如何开始：说明工程师在循环外仍需承担的责任，并给出第一个 Loop 的搭建路径。

阅读时建议关注

  1. 循环需要外部状态：进度和判断依据不能只存在于单次对话上下文。
  2. 生成器不能独自证明自己正确：测试、规则检查或独立评判器需要具备真正说“不”的能力。
  3. 自动化会放大错误和成本：必须设置预算、停止条件、隔离环境和人工接管点。
  4. 人的价值发生上移：工程师从逐步执行转向目标定义、循环设计、异常处理和结果验收。
